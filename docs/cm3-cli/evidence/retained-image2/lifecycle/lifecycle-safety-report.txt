Concrete findings / unmet safety expectations
A. NO ROOT EXPANSION IMPLEMENTATION. Pinned docs/cm3-cli/first-boot.md:41 explicitly states no disk expansion; the installed project wrapper explicitly avoids scanning/expanding discovered disks. Upstream retained-image admission also identifies mandatory expansion as unmet. Fixtures label already-expanded and expansion-required filesystems, but no actual implementation consumes those states. Correct root-only expansion, already-expanded no-op, expansion failure, GPT repair and preservation of /data during resizing remain NOT IMPLEMENTED / UNTESTED. No substitute grower was invented and counted as a test.
B. EXPLICIT DATA/PARTITION TARGETS ARE NOT REJECTED by the low-level U-Boot helper. An eMMC-root request does not discover or touch NVMe implicitly, but explicitly passing the unrelated data NVMe or mmcblk1p3 emits bootloader write intents and succeeds. There is no transport/root/partition/mounted-data guard. This is an unsafe interface for unattended selection, not evidence of an accidental automatic NVMe choice in normal boot. Caller responsibility cannot be mistaken for storage-selection protection.
C. PARTIAL WRITE INTENT BEFORE MISSING PAYLOAD FAILURE. With idblock.img present but u-boot.itb absent, update_bootloader records two idblock writes before returning nonzero with Missing U-Boot binary. Payload preflight is incomplete. The harness reproduced intent only; no disk was partially written.
D. MASKROM LOADER ERROR IS IGNORED. Injecting status19 for rkdeveloptool db, while later wl/rd succeed, still records write and reset and exits0. This corresponds to maskrom || true in the installed script. It may be intentional for an already-loaded device, but does not prove the device is ready or safe to write. Hardware recovery remains UNTESTED.
E. READINESS DOES NOT ESTABLISH IDENTITY FRESHNESS OR KEY VALIDITY. OpenSSH -A preserves existing host keys; a nonempty mode0600 stale/invalid Ed25519 private-key fixture survives and enroll/check accepts it. The machine-id check validates nonzero lowercase hex syntax, not cross-device uniqueness. Source tests already use a fixed valid ID. These are demonstrated limits, not a claim that the actual clean retained image contains stale keys or duplicate IDs. Upstream offline extraction found no build-time machine-id or SSH host keys. Actual systemd generation of a fresh machine-id was not run here; fresh SSH identity generation from absent files was exercised with host OpenSSH.
